# FLAKY 重复执行详情验证

更新日期 2026-10-08。分支 `codex/flaky-details`，基于用户批准合并的运行管理 PR #15。

## 已实现

执行器过去只保留用于最终判定的那次结果，`result_to_storage` 一直把 repeat 写为空列表。现在 repeat 大于 1 时，每次经过响应/轨迹限制与确定性 Judge 后保存独立快照，包含次数、计划重复数、是否实际执行、状态、通过标记、违规、响应、轨迹、错误、延迟与截断信息。深拷贝发生在最终 FLAKY/取消/无工具验证修改之前，不会把最终状态误写成每次状态。

取消检查会保存一个 CANCELED、executed=false 的标记，剩余重复不虚构执行。瞬态重试属于同一次重复，不产生额外记录。LLM 裁决仍每用例一次。最终状态、选用的主执行、分数、进度、指标、回归分类及门禁算法没有改变。

每个已保存用例提供“重复执行详情”，FLAKY 按钮明确注明 FLAKY。详情显示计划、实际执行、保存条数与最终状态，表格逐次列状态、延迟和轨迹数量，可看任意一次，也可对比两次的状态、延迟、违规、响应与轨迹 JSON。显示值使用文本节点，不执行 HTML。刷新后从数据库重新读取，查看与对比不会重跑 Agent。无详情时明确说明旧记录或单次执行无法还原，不伪造历史数据。

## 接口与边界

| 请求 | 输入与结果 |
|---|---|
| `GET /api/executions/{id}/repeats` | offset 非负，limit 1..20、默认 10；返回 execution_id、run_id、test_case_id、final_status、available、requested、total、executed、offset、limit、has_more、items |
| `GET /api/executions/{id}/repeats/diff` | left/right 为从 1 开始的次数；返回两次显示内容、response_diff、trace_diff、新增/移除违规及 limited |

两者都要求既有 API 认证。未知执行或次数返回固定 404；参数错误去除输入与错误上下文。接口没有写操作，没有输入适配器、路径、端点或门禁参数，也没有增加 Agent 工具。

网页视图使用凭据字段脱敏、凭据文字脱敏及已有网页路径/环境变量脱敏。快照不保存 adapter-native raw，避免绕过响应和轨迹限制。轨迹以格式化 JSON 文本展示；响应、错误、轨迹文本各最多 20000 字，轨迹最多 200 条，单份差异最多 20000 字，截断有明确提示。比较针对脱敏后的显示内容，达到上限时不声称范围外无差异。

## 数据兼容

使用既有 `executions.repeat_json`，没有新增列或迁移。旧空列表原样保留，详情返回 available=false、requested=null、items=[]。测试在旧空数据上重新创建 Store 并核对运行一致，也在新保存数据上重新创建 Store 后读取和对比。删除到回收站的执行仍按 ID 可读，沿用 PR #15 的证据保留规则。

过程证据通过 TestResult 私有属性保存，现有 CLI/API 结果 JSON 不新增字段；单次执行仍写 repeat=[]。已有 JSON 导出会自然包含新重复运行的证据，旧记录和旧命令输出格式不变。逐次对比暂为网页功能。
