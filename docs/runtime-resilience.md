# 运行可靠性和门禁迁移

本分支处理 Python 超时、同名模块缓存、Agent 会话恢复、进程间项目互斥、门禁默认策略和偏好浏览器等待竞态。改动登记在 Unreleased，不改变已发布 v1.0 的 tag 或包版本。

## 门禁

所有严重度的 ERROR 和 FLAKY 默认阻断。首次没有基线时也检查，历史 ERROR 同样阻断。critical/high 新行为回归继续由 fail_on 控制，历史行为 FAIL 不单独阻断。LLM 建议不改变门禁。

需要保留 v1.0 策略时显式配置如下。

```yaml
gate:
  fail_on: [critical, high]
  block_errors: false
  block_flaky: false
```

两个开关可以独立关闭。CLI 的 --fail-on 只覆盖行为回归严重度，不能关闭质量检查。CLI、网页和 Agent 共用判定，Action 沿用 CLI 退出码。质量检查失败的运行不会通过 run --set-baseline 自动设为基线；管理员显式选择历史运行设为基线的入口继续保留。

这是经用户选择的默认行为变更，可能让原来通过的 CI 失败。公共配置快照新增两个可选布尔字段，均默认 true。发布前需要单独决定版本和审核迁移，不将快照更新当作无兼容影响。

## Python 执行

每次用例都在新进程中导入和执行，包括验证阶段。同步、异步和函数内部延迟导入均使用该进程。项目 Python 源码重新读取，不依赖旧 pyc。配置目标不导入服务进程；注入 callable 通过 cloudpickle 传入 worker，返回只解析 JSON，不能通过返回 pickle 在宿主执行代码。

超时或取消终止进程树。Windows 使用不可脱离的 Job Object，POSIX 使用独立进程组。正常完成也清理子进程，避免留下后台工作。这个机制不是限制目标代码权限的安全沙箱，POSIX 中主动脱离进程组的恶意程序不在保证范围。

每次进程启动有开销，全局变量不会与宿主或下一用例共享。需要保持服务状态的 Agent 可以使用原 HTTP 适配器。新增 cloudpickle 运行依赖。其他框架适配器在宿主加载的对象不具有此 Python worker 隔离保证。

## 会话与互斥

检查点存入原数据库的私有 agent_session_checkpoints 表，使用 JSON，单会话上限 2 MB，保存聊天、工作流位置、待审批参数与绑定、已处理审批及上下文，不保存 SDK client 或密钥。持久化内容脱敏，审批参数若因此改变，恢复后拒绝执行。

首次升级建表也使用数据库范围的 OS 锁，避免多个 worker 同时启动时重复建表。测试让四个独立进程同时初始化，确认均能完成。

重启后可以从网页历史继续原会话。恢复仍要求原账号、原登录身份和项目编辑权限，配置必须一致。审批执行时重新校验文件哈希。退出登录或撤销权限不能通过恢复绕过授权。

先持久化操作意图，再调用模型或执行批准动作，完成后保存结果。如果进程在操作中途退出，结果可能已经产生，不能判断是否安全重放。该会话只供查看日志，页面提示查看运行和日志后新建会话。不会自动重做审批，也不声称从任意程序执行位置继续。

每项目配置最多八个会话，空闲一小时过期。数据库更新时间决定淘汰顺序，忙会话不删除，名额全忙返回 429。同步和流式请求共享同一 OS 会话锁，另一个 worker 取得锁后先刷新最新检查点，重复审批只能执行一次。

项目运行和会话锁默认在同一用户的临时目录 specagent-locks 中，由 OS 管理，进程退出后自动释放。锁元数据放在项目之外，Draft 等只读操作不创建项目文件。可用 SPECAGENT_LOCK_DIR 指定共享的绝对锁目录，容器需要显式挂载并使用同一锁目录。CLI、网页和 Agent 必须使用相同的配置绝对路径、数据库和锁目录。Agent 日志目录仍需可写。同机 worker 默认共享用户临时目录；不同主机不在保证范围，本改动不承诺分布式锁。

## 浏览器等待

基线标签先渲染，身份翻译由下一动画帧执行。测试现在等待翻译结果，再运行原有标签与身份断言。新增检查刻意暂停动画帧，证明标签已出现时翻译仍未完成，随后恢复动画帧并验证正确结果。不使用重跑来掩盖失败。

## 验证

tests/test_runtime_resilience.py 使用真实子进程验证死循环、取消、子进程清理、并发同名模块、进程锁争用和崩溃释放。独立服务进程恢复待审批动作，执行一次后原进程再次审批返回冲突。还检查聊天与停放调用恢复、日志截断、配置和规格变更、凭据脱敏、操作中断，以及首次 ERROR/FLAKY 的 CLI、网页和 Action 评论一致性。

原账号测试增加重启恢复后的跨账号隔离、退出与权限撤销检查。原浏览器断言保留。全量测试、安装包和 GitHub CI 的最终结果在 PR 中登记。
