# 实时运行进度验证

分支 `codex/run-progress`，基于已合并的修复建议 PR #10。网页审计、项目运行、Verify 与批准后的 Agent 执行记录真实用例完成进度。CLI 默认输出和持久化顺序不变。

快照包含已完成/总用例数、通过、失败、不稳定、错误、取消、最近完成的用例及其位置。并发运行按实际完成顺序更新；重复和重试只计一个用例。执行中计数标为暂定，整轮无工具调用的降级仍使用原有规则，之后确认最终计数。新增只读 API 使用既有认证和脱敏，取消权限只来自当前进程的活动注册，持久快照不能重新赋予权限。

`run_progress` 为独立表，旧数据库通过既有 create_all 自动建表，不修改旧运行或执行列。旧运行回退到已有最终摘要，不虚构执行历史。服务重启后可回看最后快照，但不恢复执行。网页按 500 ms 轮询，旧请求不会覆盖新运行，完成或错误时停止轮询。

验证只在临时项目和数据库上进行，没有读取或写入 `.env`，没有真实模型或外部服务调用，没有改动仓库示例。

- 新增 **9** 项测试，验证阻塞套件结束前已能读到 2/3 的真实结果、乱序完成、重复与重试、FLAKY、取消、最终全局降级、空套件、旧数据库升级、认证与 404、重启后的取消权限，以及网页 Verify 和批准后的 Agent 记录。
- 本机全量 **620 项通过**，11 个既有警告。最后的取消权限检查另跑进度与稳定性 **25 项通过**。
- 原有浏览器 **85** 项检查与断言保留，新增 **7** 项，共 **92** 项通过。真实慢速 FinCare 副本在结束前展示递增计数；新页面使用同一 token 查看同一运行，取消后未开始用例记为 CANCELED，最终计数与数据库一致。页面没有脚本错误。
- 19 组既有 CLI stdout 字节和退出码再次一致，见 [逐项证据](run-progress-cli-output-evidence.json)。

GitHub CI 的结果记录在 PR 中。没有做真实提供商、多进程执行恢复或 PostgreSQL 实机验证。
