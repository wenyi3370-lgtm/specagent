# 基线历史验证

更新日期 2026-10-08。分支 `codex/baseline-history`，基于用户批准合并的 FLAKY 详情 PR #16。

## 已实现

基线历史显示当前基线及设置、替换、重新设置和取消的 UTC 时间、操作者、入口、原运行与新运行。每页 20 条，可以前后翻页。原运行和新运行可点击查看，运行移入回收站后仍可按 ID 读取证据。刷新页面重新读取数据库，不重放操作。

网页身份由服务端确定。配置共享令牌时显示共享令牌用户，没有令牌的本机模式显示本机网页用户；共享令牌不能识别个人。命令行取本机进程用户名，身份类型为 os_user，这不是账号认证结果。Agent 保留对应操作者并标为人工审批入口，不改变 human_only 门禁。直接调用 Store 的未归属操作明确标为未识别本机调用者。记录不保存令牌值，客户端不能提供身份字段。

取消前显示对默认对比和新回归趋势的影响，要求输入完整当前运行 ID。服务器同时检查最新历史版本，期间更换、重新设定或取消过基线都会拒绝旧确认，包括换走后再换回同一 ID。取消只清除当前标记，保留所有运行、规格、执行证据和审计事件，刷新指标和趋势。原历史 CI 结果保留，无基线趋势显示未评估；显式指定旧运行 ID 的对比仍可读取。

## 接口

| 请求 | 输入与结果 |
|---|---|
| `GET /api/baselines/history` | 必传 project_id，长度 1..64；offset 非负；limit 默认 20，范围 1..100。返回 current、revision、legacy_current、items、total、offset、limit、has_more |
| `POST /api/baselines/clear?project_id=…` | JSON 只接受 `confirm_run_id` 和必传可空 `expected_event_id`；核对最新基线与版本，不匹配返回固定 409 baseline_changed。返回更新后的历史 |

取消示例为 `{"confirm_run_id":"run_example","expected_event_id":"baseline_example"}`。仅旧数据库已有基线且尚无审计事件时，revision 为 null，取消请求也需显式传 null；缺少该字段返回 422。

两者沿用 API 认证。新增 POST 要求 JSON，本机无令牌模式检查环回 Host；错误不回显输入值和异常上下文，内容使用统一网页脱敏及文本节点。项目 ID 在查询参数中编码，支持已有包含引号或斜杠的 ID。历史及取消暂为网页功能，不新增 CLI 或 Agent 子命令。旧设置接口的请求与结果保持兼容。

## 数据与并发

新增 `baseline_audit` 只追加事件，使用序号稳定排列同秒操作，以事件 ID 作为取消确认版本。基线标记和历史记录在同一事务提交。先取得项目行写锁，再读取当前状态和审计版本；失败设置、回收站设置、过期取消不产生事件，也不抹掉原基线。

已有数据库自动创建新表，不改变运行字段。旧基线的原设置时间和操作者未知，页面明确注明，不生成虚构事件。旧基线取消时记录本次已知操作。审计引用没有随运行删除的级联操作，回收站保留证据。CLI 与 API 原有结果 JSON 不新增审计字段，命令输出不受影响。
