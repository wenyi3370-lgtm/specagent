## 各 PR 的共同要求

只在临时项目和数据库上测试，不修改仓库示例，不读取或写入 `.env`，不使用真实 LLM 测试，不把密钥放入日志或截图。旧测试保留，新操作有等价命令提示，新增 API 有认证、输入校验与路径安全测试。需要数据库迁移的工作必须验证已有数据库升级。

代码、接口、浏览器实际操作、文档和 CI 都通过后才能把事项标为已完成。真实模型、外部通知和未验证的平台必须单独说明。PR C 的真实模型演示只有用户通过进程环境提供 key 后才可验证，没有 key 时明确标为未在本次验证，不能编造模型输出。

## PR C 的范围约束

新增 `suggestions list/show` 与只读建议接口。原始 `fix.diff` 按字节读取和下载。建议 ID、目录包含关系与符号链接必须验证。建议与复验记录只能存在服务端项目下的建议目录。Agent 面板仅增加查看建议链接，可视化本身由独立 PR 交付。CLI `triage` 只有发现对应修复前运行的建议时才追加提示，没有建议时输出保持不变。
